# StudyPal 五人开发任务分配表

更新时间：2026-05-26

本文档基于 `development-task-list.md` 中列出的 90 项任务重新分配。分配逻辑按照实际开发顺序组织：先明确需求和数据基础，再做后端基础能力，再做核心业务闭环，同时推进前端页面，最后由测试和文档完成验收与交付。

如果小组已有真实成员姓名，可以直接将“同学 A-E”替换为对应姓名。

## 开发顺序建议

| 阶段 | 先做什么 | 主要负责人 |
| --- | --- | --- |
| 第 1 阶段 | 需求范围、MainTask 规则、角色权限、接口表、数据库脚本验证 | 同学 A |
| 第 2 阶段 | 登录/当前用户、Session、权限、课程管理、学生选课 | 同学 B |
| 第 3 阶段 | MainTask 发布事务、AI/fallback、StudentSubTask、StudySession、Dashboard 数据 | 同学 C |
| 第 4 阶段 | JSP 页面、表单、弹窗、按钮权限、错误和空状态、Dashboard 展示 | 同学 D |
| 第 5 阶段 | 全流程测试、打包验证、README、requirements、演示和答辩材料 | 同学 E |

## 核心联调链路

五个人开发时，至少要保证下面这条链路可以完整跑通：

```text
用户登录或切换身份
-> 学生加入课程
-> 教师发布 MainTask
-> 系统生成 SubTaskTemplate
-> 系统为已选课学生生成 StudentSubTask
-> 学生更新子任务进度
-> 学生记录 StudySession
-> Dashboard 展示进度和学习统计
```

## 注意事项

| 注意点 | 说明 |
| --- | --- |
| 混合任务处理 | 标记为“后端/前端”的任务需要同学 C 或 B 提供后端能力，同学 D 完成页面交互 |
| 测试提前介入 | 同学 E 不需要等全部开发结束，可以在每个模块完成后立刻验收 |
| 接口表持续更新 | 同学 A 维护接口表，前后端每完成一个功能就更新一次 |
| MainTask 规则先定 | 是否允许编辑/删除 MainTask 会影响数据库、后端、前端和测试，必须优先确认 |
| 演示链路优先 | 如果时间紧，优先保证核心联调链路跑通，再补低优先级遗留功能清理 |
