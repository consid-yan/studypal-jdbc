一、 数据库整体设计思路概述
用户权限分离（RBAC基础）： 系统废弃了将所有用户字段揉杂在同一张表中的做法，采用 USER_ACCOUNT 作为统一身份认证基表，分离出 PROFESSOR（教授）、STUDENT（学生）和 ADMIN（管理员）三张角色详情表。这保证了数据的隔离性，避免了大量空字段（NULL）的出现。

选课关系（多对多映射）： 通过 ENROLLMENT（选课表）打破 STUDENT 和 COURSE 之间的多对多关系，实现标准的关系型映射。

任务管理的动静分离：

主任务（MAIN_TASK）： 定义宏观任务。course_id 允许为空（支持关联课程的“课程任务”，也支持不关联课程的学生“自主任务”）。creator_id 指向基表，意味着教授或学生都可以创建任务。

模板与实例分离： SUB_TASK_TEMPLATE 定义了任务的标准化子步骤（如：看视频、写报告），而 STUDENT_SUB_TASK 是学生认领后的实际执行实例，学生可以修改自己的计划时间和标题，且不影响原模板。

三、 表之间的核心联系 (Relationships)
整个系统的运转主要依靠以下四条核心链路：

用户身份链路 (1对1 / 1对0)：

USER_ACCOUNT 是核心。系统登录时读取 USER_ACCOUNT，然后根据 role 字段去查对应的 PROFESSOR, STUDENT, 或 ADMIN 表获取业务详情数据。这种设计极其方便后期新增用户角色（如：助教）。

教学链路 (1对多对多)：

教授授课： 1名 PROFESSOR (通过 lecturer_id) 对应多门 COURSE。

学生选课： 1门 COURSE 和多名 STUDENT 通过 ENROLLMENT 中间表实现多对多关联。

任务分发链路 (1对多)：

课程任务生成： 1门 COURSE 对应多个 MAIN_TASK。

任务拆解： 1个 MAIN_TASK 包含多个标准化的 SUB_TASK_TEMPLATE。

学生执行链路 (1对多)：

任务认领/实例化： 当一个主任务发布给某个班级后，系统会为选了该课的 STUDENT，根据 SUB_TASK_TEMPLATE 生成对应的 STUDENT_SUB_TASK 记录。

STUDENT 1:N STUDENT_SUB_TASK：学生通过查询此表来查看和管理自己的待办事项列表。

一、 整体实现建议
技术栈严密对齐（MVC 模式的 JSP 实现）：

表现层 (View)： 采用 HTML 编写静态页面与交互表单（<form>），通过 POST/GET 提交给后端（PPT 07）。

控制与业务层 (Controller/Service)： 采用 JSP (JavaServer Pages) 接收请求参数（request.getParameter），利用内建隐式对象（如 session、response）控制页面跳转与逻辑处理（PPT 07）。

数据访问层 (DAO/JDBC)： 编写纯 Java 类或方法，通过 JDBC 驱动连接 MySQL，执行 SQL 语句（PPT 06）。

持久层 (Database)： 使用 MySQL 关系型数据库存储物理表数据（PPT 02-05）。

安全性首要原则（防范 SQL 注入）：

根据 PPT 06 的安全警告，用户输入是极其危险的。在编写任何带有参数的 SQL 语句时（例如：登录认证、按课程名搜索任务等），严禁使用字符串拼接（Statement），必须全量采用 PreparedStatement 绑定参数 ?。

合理运用会话管理（Session）：

系统包含学生、教师、管理员三种角色。用户登录成功后，必须将用户信息和角色（Role）存入 JSP 的 session 对象中（PPT 07）。在进入敏感页面（如发布任务、选课）前，先通过脚本片段（Scriptlet）校验 session，防止未登录用户越权访问。

数据库映射规范性：

按照 PPT 10（Mapping 规范）的第 8 步，正确处理 USER_ACCOUNT 基表与 STUDENT / PROFESSOR 子表的外键关联。确保在物理建表时，声明好外键约束及级联策略（如 ON DELETE CASCADE），以维护引用完整性。

二、 具体实现步骤顺序
为了降低开发复杂度，建议采取“迭代式、模块化”的开发顺序，从底层数据库逐步向上构建：

第一阶段：数据底座与环境搭建
第 1 步：编写建表脚本并初始化 MySQL 数据库

怎么做： 依据之前梳理的实体关系（EER 映射），在 MySQL 中执行 CREATE DATABASE 和 CREATE TABLE 语句（PPT 03）。为所有表建立主键（PRIMARY KEY）、外键（FOREIGN KEY）、唯一约束（UNIQUE）和自增主键（AUTO_INCREMENT）。

第 2 步：开发环境配置与项目初始化

怎么做： 下载并配置 Apache Tomcat 服务器（PPT 07），在 IDE（如 Eclipse 或 IntelliJ IDEA）中创建一个 Dynamic Web Project。将 MySQL 的 JDBC 驱动 jar 包（mysql-connector-java.jar）放入项目的 WEB-INF/lib 目录下。

第二阶段：核心底层代码（数据通道）开发
第 3 步：编写数据库连接工具类（DBUtils）与实体类

怎么做： 创建一个标准的 Java 类，使用 Class.forName() 加载驱动，通过 DriverManager.getConnection() 获取数据库连接（PPT 06）。同时，为数据库中的每张表编写对应的 Java 类（POJO/JavaBean，如 User.java, Course.java），用于在 JSP 中传递和封装数据。

第三阶段：功能模块渐进式开发（由浅入深）
第 4 步：实现用户认证与会话管理模块 (User & Session)

怎么做： 编写登录页面（login.html），通过表单提交给 login.jsp。在 JSP 中使用 PreparedStatement 查询 USER_ACCOUNT 表，核对密码。若成功，用 session.setAttribute("user", user) 记录状态，并根据用户角色重定向（response.sendRedirect）到不同的主页（PPT 07）。

第 5 步：实现课程与选课模块 (Course & Enrollment)

怎么做： * 教师/管理员角色：实现“创建课程”表单，向 COURSE 表插入数据。

学生角色：实现“课程列表查看”与“点击选课”功能。选课动作会向中间表 ENROLLMENT 插入一条记录（结合 PPT 04 的多表查询，让学生能看到自己已选的课程列表）。

第 6 步：实现核心任务与进度管理模块 (Task & Progress)

怎么做： * 任务发布： 教师选择具体课程，填写主任务和子任务模板，数据写入 MAIN_TASK 和 SUB_TASK_TEMPLATE（PPT 03 插入多表）。

任务实例化： 当学生查看课程任务时，系统检查 STUDENT_SUB_TASK 是否有记录，若无则自动根据模板为该学生生成专属的子任务实例。

进度更新： 学生在前端勾选“完成”，通过 JSP 执行 UPDATE 语句更新 STUDENT_SUB_TASK 的 status 和 completed_time（PPT 03 更改数据）。

第四阶段：优化与系统测试
第 7 步：异常处理、防注入检查与全面测试

怎么做： 检查系统是否存在直接拼接 SQL 的地方；测试当删除一个课程时，其下的任务和学生的选课记录是否通过级联删除（CASCADE）被正确处理；使用 JSP 注释和 HTML 注释规范代码（PPT 07）。
